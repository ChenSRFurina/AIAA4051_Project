# Explore 成功参照检索实验与课程收尾

[本机 SearchQA 实验报告](index.html) · [逐题与成本 JSON](summary.json) · [实验设计与源码签名](design.json) · [已核对的两套固定 ID](fixed_ids.json)

最终 dev 正确数为 B 24/30、C2b 23/30、C2c 23/30，对应 F1 为 84.44%、82.22%、82.22%。C2b 与 C2c 均选回初始化技能，三十题预测相同。B 多答对的题目要求识别《I, the Jury》的作者，B 给出 Mickey Spillane，另外两组给出 True。相同逻辑调用和生成 token 上限下，三组的正确数仍为 24、23、23。

C2c 的实际成功配对曝光从同机 C2b 的 2/18 增至 8/18，涉及的不同失败题从 1 道增至 3 道。新增的 6 次曝光由两种不同题对产生。其中 4 次把“将稻草纺成金子的童话人物”与 Joseph McCarthy 的人物识别题配在一起。答案类别相同，解题所需线索却不同。六个 C2c 候选都没有修复其父代的 dev 错题。新规则确实扩大了覆盖，分数收益则未出现。三组含一次共享初始化共 829 次物理调用、39,009 生成 tokens，实际分配 0.215 GPU·h。

C2c 测试一个具体假设。SearchQA 的陈述式线索经常用 “this author” 或 “he” 隐含所求实体，原 C2b 容易将这类线索归入 unknown，因而找不到跨题参照。C2c 对原规则未找到参照的失败增加一次基于问题文字的匹配。候选参照来自该方法当时已经观察到的训练成功，同一份反馈优先使用不同成功题。这些规则仅改变交给技能优化器的成功例。C2b 与 C2c 使用相同的诊断、证据压缩、失败抽样、算子、候选数与选择规则。

主比较是同机 C2c 对同机 C2b。B 是使用同一初始化、数据和硬件重新运行的补充参照。三组均使用 SearchQA 固定 dev 的 30 道题选优，实验范围为 train/dev。报告提供最终逐题预测，以及候选相对父代的修改、修复与退化。另有固定历史训练轨迹的检索重放，涵盖 SearchQA 与公开版 HotpotQA。后者的配对数是离线过程指标。

## 课程剩余工作

1. **课程 HotpotQA 划分。** 向课程负责人索取 Project 5 提供的划分文件或固定 ID、答案和评测说明，并确认是否与公开 distractor 版对齐。课程文件列出的联系人为 Jiujiu Chen，邮箱为 jchen349@connect.hkust-gz.edu.cn。建议同时说明已用公开版完成 100 train / 30 dev，以便确认哪些部分可以复用。拿到划分后先核对 ID 和重叠，锁定用于报告的方法与配置。若训练或验证集合不同，按课程划分重做相应的共同初始化和 B/C 训练，再评测冻结的 N/I/B/C，导出 EM、F1、延迟及完整错题清单。若仅新增 test，即使 train/dev 完全一致，现有冻结入口也校验完整 manifest 的哈希。最直接的做法是用课程完整 manifest 在新目录重跑，再走现有冻结评测；若计算资源紧张，则先实现并测试一个仅追加独立 test 的入口，逐项验证历史 train/dev、技能和模型签名并留下两份 manifest 的关联记录。
2. **GPU 与服务信息。** 本机实验的两个 GPU 会话均有开始、结束与实际分配时数，见结果 JSON 的 gpu 数组。对历史托管结果，向部署者索取硬件、精度、权重 revision、运行时段及可归属的分配记录。在给定口径下能核实多少就填写多少，将未知部分列入成本表。请求耗时与分配时间应分别记录。
3. **六页报告与演示。** 第 1 页给研究问题，第 2 页写数据划分、初始化及选择，第 3 页对照 B、C 和 Explore 扩展，第 4 页给冻结后的主结果、延迟和预算，第 5 页以候选差异和错题分析解释局部修复及退化，第 6 页写结论和局限。将逐题输出、完整图、固定 ID 和成本记录作为附件。演示可以从同一条训练失败开始，展示成功参照、优化器收到的反馈、采用的技能差异和逐题 dev 变化。正式项目结论优先使用已封存的 C 主对照，本次本机实验单列为方法探索。
4. **下一次改动的决策依据。** 先读本次新增的所有不同题对，标记它们是否同时示范了失败题需要的证据操作与答案形式。若继续实验，建议只改其中一个环节，并先用 train 轨迹检查是否选出了更合适的参照。独立泛化结论需要在方法冻结后，用课程允许、尚未用于开发的评测集验证。

## 本次归档的运行入口

原始日志和账本位于本机 `Explore/runs/local/c2c-20261123-searchqa/`，读取报告无需模型服务。以下命令对应本次本机实验，从仓库根目录运行。重新训练时要准备新会话目录，复制本次 config.json 和运行前的 design.json，并启动本地服务及 GPU 账本。已完成的运行目录应保留供复核。

```powershell
conda activate qwen3.5
$s = 'Explore/runs/local/c2c-20261123-searchqa'
# 离线重放历史训练参照，可指定自己的输出文件。
python api/check_clue_retrieval.py "$s/historical_train_replay.json"
# 原始会话存在时，重建离线结果与 HTML。
python api/report_clue_comparison.py $s results/20261123 --first-gpu-session 4070-qwen35-20261123-171224
```

新实验的启动顺序是 Baseline 的 initialize，然后是 `api/run_clue_comparison.py <新会话> C2c` 和同一入口的 C2b，再用 Baseline 的 train 执行 B。各组指向同一份本机 shared_init。源码及参数哈希、模型与服务来源记录在 design.json 中。历史托管对照见 [11 月 10 日结果](../20261110/summary.json)。
