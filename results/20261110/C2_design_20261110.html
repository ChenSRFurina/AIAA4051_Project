1 · 先解释“没有提升”发生在哪一层

两套 C 最终均保留共同初始化的最佳技能。SearchQA 六个候选为 22、22、22、21、22、21 / 30，起点 22/30；HotpotQA 为 18、17、17、15、16、18 / 30，起点 19/30。问题是没有产生超过起点的可选候选；不是最终选择器把更差的新技能覆盖了起点。

参照少，但不是完全没有成功经验

36 次失败曝光只有 6 次有成功参照，实际只涉及 3 道不同题目。12 次算子中 6 次完全回退到 B。没有产生任何跨题同任务配对。

SearchQA 的 18 次失败全部被粗分类器判为 unknown。HotpotQA 的 14 次未配对都有同类型成功候选，但其最佳同类型词面 Jaccard 仅 0.071–0.176，均未达到 0.2。

不能直接降低阈值

重放显示，SearchQA 若只取消 unknown 限制，两次新增词面候选会把“橡胶是哪类口香糖的成分”和“航空博物馆属于哪个机构”配在一起，Jaccard=0.222。两者共享虚词，不足以证明纠错策略可迁移。

建议先验证参照的目标类型、关系结构与证据充分性。覆盖率上升本身不算方法进步。

2 · 三组实际配对的问题

SearchQA：True → Smithsonian Institution

这是明确的回答类型差异：题目要机构名，失败输出为布尔值。成功答案与机构归属片段实际已进入反馈，不能归因于这组完全没有证据。

但首个 mutation_other 采用的修改主要是 Exact Matching，甚至把 Arthur、Ronald Reagan 等其他训练题实体写入通用技能。与同题成功最直接相关的“声明式线索仍应回答实体”没有成为清晰、带适用边界的修复规则。候选相对父代 dev 修复 1、退化 1，净增为零。

HotpotQA：两组都不证明关系链失败

商场题的失败与成功是同一实体集合的相反顺序，失败 F1=1；导演题是 Stephen Verona 与 Verona，完整响应都沿 Janet Leigh → Boardwalk → Verona 得到同一导演。它们可提供输出形式监督，但不能据此声称“成功推理取代了失败推理”。

实际商场反馈的上下文只有 Santa Rosa Rancheria 干扰段；导演反馈的上下文是另一部电影，响应片段停在演员识别部分。预测答案字段保留了，但支持答案的末端证据和完整关系链没有保留。

当前管线先把每个字段截成 160 tokens，再按总预算缩到 100 等长度。总反馈上限 2048 不是唯一问题：即便尚有余量，已经丢掉的原文后部也无法恢复；无配对项还重复携带结构化字段及原失败反馈，挤占预算。

3 · “建议改了”与“技能真的改了”不同

两数据集各 12 候选BC解释
范围外内容被舍弃48作用范围按设计约束；不表示整个候选失效
实际新增 gold 相关指令46计数按实际新增行，不把 notes 当实现；不等于 test 泄漏
与父代相同的技能01C 的 SearchQA 第三轮 mutation_other 为 no-op

mutation_other 只采用 Global Guidance；mutation_graph 采用 Node Lists/Task Graphs。原始新技能超出此范围的部分按设计被丢弃。例如 SearchQA g1 mutation_other 的 notes 声称修改 Extract Evidence，实际节点未改变。应让反馈适应这个合同，不应取消合同以追求表面改动量。

实际新增指令还出现“if the gold answer…”“match the gold standard…”等用语。推理时没有 gold，这些规则不可执行或无效；某些训练实体也被复制进技能。此类问题在 B 同样存在，不能全部归咎于 C，也不能误称为发现了 test 标签泄漏。

SearchQA 的 B 获胜候选确有一条限制布尔回答的全局指令，与它修复声明式线索的现象相容；但该指令也错误地以 gold 为条件。下一版应把条件改成推理时可观察的问题目标，而不是照抄 B 的 gold 依赖句。

4 · 推荐 C2b：先修反馈质量，再扩展检索

优先级拟新增模块实现要求验收
P0Explore/explore_v2/diagnostics.py区分格式、集合排列、可能别名、目标类型、证据缺失/冲突、未知；保持原 EM/F1 和失败 ID。高 F1 只能提供诊断线索。商城集合排列不归为多跳错误；Verona 全名/姓氏差异不归为第一跳错误；True/机构名识别为目标类型差异。
P0Explore/explore_v2/evidence.py从完整原始记录选择相关 doc/sentence、响应的引用和结论附近窗口；保留 source hash/offset、精确原文。规范化空白仅用于定位，不改写原文。所有片段能回指；保留 Boardwalk→Verona 等必要链段；不以无关文档前缀替代证据。
P0Explore/explore_v2/feedback.py明确训练参考只用于诊断；建议使用触发条件→检查→行为，并写出应保留行为及不确定性；同包给出 other/graph 的条件性作用范围约束。最终技能只依赖 question/context；检查实际采用的 diff，记录 gold 依赖、训练实体复制和 no-op。
P1Explore/explore_v2/pairing.py同题同上下文优先；跨题先匹配目标类型、关系链/比较/集合结构，再按去停用词、实体弱化的词项检索排序。弱参照明确降级；不强行配对。用低词面重合的结构正例及高词面重合的结构负例验证；不能因提高覆盖而降低可比性。
P1api/diagnose_c2.py只读审计证据保留、配对类别、采用范围、no-op 和模型费用；第一版保持现有记忆容量与去重规则。不增加采样或评审模型；审计不拒绝候选、不额外重试、不改变选择。

继续选课程 Option A。模型、QA 提示、固定 train/dev、随机 k=3 失败抽样、记忆容量、三轮两候选、父代/幸存者选择和预算保持不变；改变的是优化器收到的材料。第一阶段不增加成功采样器、评审模型、额外 QA 或自动重试。

一个反馈包应回答的七个问题

  1. 两份输出在什么可观察位置不同？明确是诊断假设，不冒充内部节点执行轨迹。
  2. 差异属于答案形式、可能别名、目标类型还是有证据的关系/事实错误？是否存在替代解释？
  3. 成功参照与本题共享什么条件？跨题参照只能支持抽象策略，不把另一题答案当证据。
  4. 哪些 context 原句及响应片段支持这一判断？保留 doc/sentence、字符位置与 hash。
  5. 建议只在什么触发条件下生效，执行什么检查，改变什么行为？
  6. 哪些原有行为应保留？例如真正的 yes/no 问题和有序问题不应被误伤。
  7. 当前算子能修改哪个区域？最终技能是否只依赖 question/context？

反馈预算分配草案

维持 2048 tokens：全局约 160，三个包各约 600（包含 JSON 开销），余量约 88。每包优先级为问题与最终答案、相关证据、关键响应片段、诊断及保留条件。使用 tokenizer 测量序列化后的总数，先移除重复与无关文本；不能装下完整证据时明确降级，而不是静默切掉最后一跳。

这只是初始分配，需要离线重放验证，不声称当前实现已经达到。低覆盖也可能合理：没有可信参照时应保留未配对状态。不要为覆盖率强配；先给检索负例，再调阈值。

版本与实现顺序

新增 Explore/explore_v2/，保留旧 Explore/explore/。先实现 diagnostics、evidence、feedback，形成 C2b 的可运行输入层；然后接只读审计和离线回归检查，最后再实现结构相似检索。代码改动属于另一次实施任务，本次只有分析工具与方案文件。

5 · 怎么判断下一版是否有效

条件变更能够回答的问题
C0原封存 C，证据保持不变历史参照
C2a只替换有关证据打包，配对选择及诊断文字沿用 C0前缀截断是否限制了反馈作用
C2b（推荐先实现）C2a + 诊断分层 + 可执行/算子范围约束最小输入整改能否产生被选中的技能提升
C2cC2b + 结构相似检索改善参照质量后，增加覆盖是否进一步有益
同期 B原失败反馈；共用新实验的初始化及固定配置避免把跨日部署差异误当方法效果

优先做 C2b + 同期 B 的完整 dev 对照；资源允许再补 C2a 和 C2c。这个设计能区分打包、综合输入整改、检索扩展，不能单独估计诊断分层与作用范围约束各自的贡献；若需要该结论，应再拆消融。

  1. 离线不变性：固定失败 ID、不读未来/dev/test 经验、来源片段可精确回指、每包总反馈不超过 2048 tokens。旧方法及历史摘要 hash 不变。
  2. 材料质量：三组已见配对作为回归样例；另按固定顺序/seed 从其余 train 样例抽查，包含未配对和检索负例，避免只对三题定制规则。分别报告评分形式与明确纠错参照，不用总覆盖率代替质量。
  3. 小规模真实算子检查：固定 train 题，检查 actual adopted diff、实体复制、gold 依赖、no-op 和实际 token；不使用旧 test 成绩调整文本。只读审计不影响候选接受/重试/排序。
  4. 完整三轮：看最终 dev 是否超过共同初始化、B/C 的逐题修复和退化、实际调用/生成 token、同上限和完整轮次共同预算截点。改善可能为零或负，不预设准确率目标。
  5. 泛化与不确定性：先由 train/dev 选版本并冻结，再评估未见数据。资源允许用预先规定的多个 seed 复核；题目 bootstrap 不能替代训练种子不确定性。

SearchQA 原 test 已看过，C2 在同一 test 上的再测只能标为探索性复测。新增独立 SearchQA holdout 需事先固定来源、去重与抽样，单独报告，不冒充课程原固定 test。HotpotQA 课程划分取得后，应按完整划分重建受影响的初始化与对照。

如果以后增加语义校验后拒绝候选、额外重试、F1 改排序或调整 QA 求解器，它们已超出本版“只改输入”的边界，需另建双方适用的协议并重新比较。
